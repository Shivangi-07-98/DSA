Static functions implications - 
Q1. this keyword cannot be used in static functions. Why?
Ans - Because static functions can be called by class name in that case this won't know which instance to point to, it knows only when called using object

Q2. non-static data members can't be used in static functions. Why?
Ans - Because static functions can be called by class name and in that case we don't know if any object exists and if they do we wont know which objects non-static data members to use.

Q3. non-static functions can't be used in static functions. Why?
Ans - non-static functions can be used by making an object inside the static function and calling the nonstatic function on it. Can't be called directly.

4. can non-static function use static data member? Why?
Ans - Yes because we have extra information available not less

Ans - Yes because we have extra information available not less

Object creation
1. Space allocation & this assignment
    Space is allocated for all non-static data members. this is set equal to the new object's address
    Data members are assigned default values (JAVA)
    0 = byte, short, int, long
    0.0 = float, double
    false = boolean
    '\0' = char
    null = everything else
2. Parsing
    Class creator's default values are assigned to data members (but only such values which are non-dynamic)
    e.g. growth multiple is set to 1.5 in ArrayList
    e.g. rehashing threshold is set in HashMap to 0.5
3. Constructor
    3.1 Default = Class creator's default values are assigned to data members (but only such values which are dynamic such as student folder or dbconnection)
    3.2 Parametrized = For class user to set values which he requires
    3.3 If no constructor is provided, Java adds the default ctor by itself
    3.4 If class creator, provides a Parametrized ctor (then Java won't add default ctor)

Variable vs Data Member

Data Member:
A variable declared inside a class but outside any method/function is called a data member.
It belongs to the object/class and represents its properties or state.

Variable:
A variable declared inside a method/function/block is called a local variable.
It is used only within that method/function/block.

Example:

class Person {

    int age;          // data member
    String name;      // data member

    void display() {
        int salary;   // local variable
        String city;  // local variable
    }
}

final keyword - 

The `final` keyword is used to restrict changes.

1. final variable (local variable)

A final local variable can be assigned a value only once.
Once a value is assigned, it cannot be changed.

Example:

void fun() {
    final int x = 10;

    x = 20;   // ERROR
}


2. final data member

A final data member can be assigned a value only once.
Once initialized, its value cannot be changed.

Example:

class Person {

    final int age = 25;   // final data member

    void fun() {
        age = 30;         // ERROR
    }
}


3. final function (method)

A final method cannot be overridden by a child class.

Example:

class Parent {

    final void fun() {
        // code
    }
}

class Child extends Parent {

    void fun() {
        // ERROR: cannot override final method
    }
}

Easy way to remember:

final variable  → value cannot be changed
final data member → value cannot be changed
final method → cannot be overridden

data member = values can't be reassigned (either assign in parsing or constructor / static block)
functions = can't override the fn in derived class (overloading is allowed in same class and derived class)
class = can't derive the final class

ABSTRACT

1. ABSTRACT CLASS

abstract class
→ We cannot create an object of an abstract class.

Why do we use it?

An abstract class is used as a common/base class for its
derived (child) classes.

Example:

            Employee
           /        \
          /          \
   HREmployee    SoftwareEmployee

Employee contains the common things of both classes,
such as name, empid, markAttendance(), etc.

We don't create a general Employee object.
We create HREmployee or SoftwareEmployee objects.

So, Employee is made abstract.


2. ABSTRACT FUNCTION

abstract function
→ A function that has no body/code.
only api - means function name, parameters, return type

Example:
abstract void doWork();

It only tells the child class:

"You must have a doWork() function,
but you decide what it should do."

Example:

HREmployee → doWork() → creates payroll
SoftwareEmployee → doWork() → writes code

So, the implementation can be different in each child.


3. WHY IS ABSTRACT CLASS REQUIRED?

→ To keep common code in one place.

Instead of writing the same common code separately
in HREmployee, SoftwareEmployee, etc.,
we put it in the Employee class.

This is what "absorb common code of derived classes" means.


4. IMPORTANT RULES

If a function is abstract
→ The class containing that function MUST be abstract.

If a class is abstract
→ It does NOT have to contain an abstract function.

An abstract class can have:
→ normal functions
→ abstract functions
→ data members
→ constructors

If fn is abstract, will the containing class be necessarily abstract? Yes
If class is abstract, will it necessarily have abstract functions? No

ABSTRACT — IMPORTANT QUESTIONS

1. If a function is abstract, will the containing class necessarily be abstract?
Yes.

Reason:
An abstract function has no body/implementation.
If the class were not abstract, we could create its object.
But then we would have an object of a class containing a function
that has no implementation.

Therefore, if a class contains even one abstract function,
the class must be marked abstract.

2. If a class is abstract, will it necessarily have abstract functions?
No. An abstract class can have only normal functions as well.

Reason:
A class can be made abstract simply to prevent its direct object
creation and to use it as a common/base class for child classes.

so abstract class → does NOT necessarily need an abstract function.

3. What happens if a child class does not provide the abstract
function of its parent?

If a child class extends a parent class that has an abstract function,
the child must provide (implement/override) that function.

Example:

abstract class Parent {
    abstract void fun();
}

class Child extends Parent {
    // fun() is missing
}

This gives an error because Child has inherited an abstract function
but has not provided its implementation.

How can we fix it?

Option 1: Provide the function in Child:

class Child extends Parent {
    void fun() {
        System.out.println("Child's implementation");
    }
}

Option 2: If Child also does not want to provide the implementation,
mark Child as abstract:

abstract class Child extends Parent {
}

Why must Child be abstract?

Because Child still has an abstract function without a body.
If Child were not abstract, we could create its object even though
the function still has no implementation.

So the rule is:

Parent has abstract function
        ↓
Child must implement it
        OR
Child must also be abstract

Interface
-> When all fns are abstract and there are no common instance data members to share
-> Similar to abstract classes
-> An extreme version of abstract classes, when all fns are abstract, no common instance data members
-> If a class implements an interface but doesn't provide body for all functions, then it will become abstract
-> Can we make an object of interface? No
-> Can an interface provide body for any function? Yes, since Java8, using the default keyword it is possible (although advised to not use). Java provided for this backword compatibility. Not to be used often.
-> Can an interface have data members? Yes, but not as instance data members, can be used as static data members

--> Instance simply means belonging to an object.
Instance data member → each object can have its own separate value.
static data member → belongs to the class, shared rather than belonging separately to each object.

Interface data members are automatically: public static final → no instance data members.
So they are class-level constants, not object-specific variables.

abstract class vs interface
-> Abstract classes can have implementations for some functions, interfaces are supposed to have all functions with no implementations
-> Abstract classes can have instance data members, interfaces can only have static data members
-> A class can't derive two abstract classes, but can implement any number of interfaces
-> Interface data members are final and static
